# Auto Work 详细使用说明

本地 Codex 批量前端开发调度面板。React + TypeScript + Vite 前端、Node.js 调度后端、Electron 桌面窗口。仅监听 `127.0.0.1`，不部署到云端。

## 打开与关闭

从仓库获取源码后，请先按根目录 README 安装依赖。Mac 执行 npm run build:launcher 编译启动器后，可以双击 **Auto Work.app**；也可使用 **启动面板.command** 或 npm start。

- 打开后出现独立桌面窗口，自动启动本地服务。
- 点击窗口左上角关闭按钮，或退出应用，会取消运行中的任务、终止其子进程、停止定时调度并释放端口。正常退出可能需要数秒。
- 工作目录、代码修改、运行记录、报告和定时配置会保留。下次打开恢复定时，不补跑错过的时间。
- 不支持关窗后继续后台运行。夜间定时任务需要应用保持打开、电脑保持开机且不休眠。
- `Auto Work.app` 是依赖当前项目目录的本地启动入口，不是独立安装包；请把整个目录一起移动，不要单独移动 `.app`。

Windows：安装下面的前置依赖和项目依赖后，双击 **启动面板.bat**。关闭桌面窗口退出服务。Windows 路径和进程树处理已实现，但本次只在 macOS 实机验证。

Mac 原生启动器源代码在 `desktop/Launcher.swift`。在另一台 Mac 或改动启动器后，可执行 `/bin/zsh scripts/build-launcher.sh` 重新编译，需要 Xcode Command Line Tools；正常使用不需要重新编译。仓库不包含本机生成的启动器可执行文件，新 Mac 首次使用需要构建。

## 前置依赖与首次安装

- Node.js 20 或更新版本（建议使用当前维护版本）
- Git
- 已安装并登录的 Codex CLI
- 目标项目使用的 npm / pnpm / Yarn

```bash
cd /你的路径/CodexQueue
npm install
codex login status
# 如果未登录：
codex login
```

Electron 官方下载若超时，可在明确愿意使用镜像时运行 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`（macOS）。

命令行启动：`npm start`。启动入口先构建再打开窗口，避免运行过期页面。Mac 启动脚本会寻找已有的现代 Node，规避 Finder 精简 PATH 或系统旧 Node；启动错误见 `data-launch.log`。

## 使用

1. 选择目标项目的 **Git 仓库根目录**，点击 **检查项目**。
2. 设置基准分支或提交（默认 `HEAD`）、并发数量（默认 2、上限 5）、单任务超时。
3. **新增任务**：填写任务名称、Git 分支名、原始开发需求 Prompt。每次执行会给分支追加批次与任务 ID。
   需求输入区支持 **添加图片**、拖拽图片和粘贴截图。支持 PNG / JPEG / WebP，每个任务最多 8 张，每张最多 10 MB。可预览、移除图片；相同文件按内容去重。原图会在规划、编码和 Review 阶段通过 Codex 的 `--image` 参数传入。
4. 在运行配置中确认校验命令，每行一条。留空时自动检测 `typecheck` / `type-check` / `check:types` 之一和 `lint` 脚本。未检测到校验命令会标记失败，不会假装校验通过。
5. 点击 **立即运行**，或进入定时运行页面点击 **设置每日定时**。
6. 在 **运行记录** 查看阶段、状态、分支和工作目录，并打开方案、Review 和日志。
7. 人工审核后，自行将任务分支合入目标分支。

任务表单修改需要点击 **保存配置**。**立即运行** 和 **设置每日定时** 会同时保存当前配置。运行中的批次持有配置快照，不会被后续表单修改改变。定时任务使用已保存配置，不会读取未保存的表单。

## 登录检查

面板调用本机 `codex login status`，复用同一系统用户、同一 `CODEX_HOME` 以及同一凭据存储环境中的 Codex 登录，不读取或保存账号密码、认证文件。浏览器登录 ChatGPT 不等于 CLI 已登录。

页面打开时检查一次，每次批次运行前再次检查。凭据状态检查不发起模型请求，无法保证网络、额度、目标模型或工作空间权限可用；这些错误会在实际执行时保留为任务失败报告。执行期间不会自动弹登录窗口。

## 执行流水线

1. 检查 CLI 登录、项目和基准提交，给整个批次固定一个提交 SHA。
2. 在目标仓库同级 `.auto-work-worktrees/<仓库名>/<批次ID>/<任务ID>` 创建独立分支和 worktree。
3. 规划：`codex -a never exec --sandbox read-only --json`，后端保存 `plan.md`。
4. 准备依赖（可关闭）：按锁文件选择包管理器；pnpm/Yarn 使用 frozen lockfile，npm 有锁文件使用 `ci`，无锁文件使用 `install`。默认禁用依赖生命周期脚本；如果项目需要生成代码或编译原生依赖，请在需求或校验命令中明确项目所需准备步骤。
5. 编码：`workspace-write` 沙箱，原始需求和完整方案通过标准输入传递；阶段结果使用 JSON Schema 约束并二次验证。
6. 独立校验：后端执行配置中的命令，记录真实退出码，不以模型的成功描述代替校验。
7. 自查：只读分析修改，输出 `todo-review.md`。完成、失败、阻塞、取消会分别记录；单个任务失败不会取消其他任务。

不使用已经移除的 `--full-auto`，不使用绕过沙箱的参数。审批模式为 `never`，权限不足会返回失败给模型，模型可以在权限范围内调整做法；确实无法继续时保留报告。Codex 本身的权限和模型限制仍然有效，不承诺所有项目都可以无需准备直接完成。

每次阶段单独启动 Codex，方案通过文本传递；使用 `--ephemeral` 临时会话模式，不持久化这些阶段的 CLI 会话 rollout 文件。记录阶段 ID 用于日志关联，但不支持恢复临时会话。当前版本重新运行会创建新批次。

## 自主决策规则

- 项目已有规范和实现 > 已安装依赖的官方推荐用法 > 成熟常见的行业做法 > 满足需求的简单实现。
- 普通技术选择自行决定并继续，不向用户中途提问；报告记录选择、理由和假设。
- 严格遵守目标仓库的 AGENTS.md，保留原始需求中的具体文案和有语义的换行。
- 缺失、冲突、无法辨认的文案不得编造，记录为待确认；能独立完成的部分继续。
- 已实现待复核决策、真正未完成事项、未验证内容分别记录。
- 不做无关重构，不提交、不推送、不合并、不清理 worktree。

## Git 行为

独立 worktree 拥有独立工作目录和暂存区，原目录的未提交修改不会自动进入新任务，也不会被调度器修改。worktree 共用仓库历史和分支引用，不是独立仓库。模型的文件操作受沙箱约束，提示词还明确禁止提交、推送、合并和修改原目录。

完成后保留未提交代码，可以在对应 worktree 中查看、测试和提交；提交后再合入原分支。不要在尚未审核前执行强制清理。

## 数据与产物

```text
data/state.json                         配置、运行历史、定时状态
data/attachments/<内容哈希>.<扩展名>       上传或粘贴的需求图片
data/worktree-records/<批次ID>.json       清理历史后保留的代码目录索引
task/<批次ID>/<任务ID>/plan.md           开发方案
task/<批次ID>/<任务ID>/screenshots/      约定的任务验证截图目录
task/<批次ID>/<任务ID>/implementation.json  实施结果、决策和待办
task/<批次ID>/<任务ID>/events.log        完整执行日志
task/<批次ID>/<任务ID>/error.log         失败或阻塞原因
task/<批次ID>/<任务ID>/changes.txt       已跟踪文件的 diff 统计
todo/<批次ID>/<任务ID>/todo-review.md    Review 清单
```

日志和原始需求可能包含业务信息，只保存在本地，不要随意公开。页面日志最多显示末尾 20 万字符，完整日志保留在磁盘。

服务意外退出后，未完成的历史任务在下次启动时标记为 **已中断**。定时同一天最多自动触发一次，批次重叠时跳过并记录原因。

## 图片、截图与存储清理

侧栏 **存储管理** 显示图片、日志、验证截图和方案报告的占用与保存路径，可点击 **打开目录**。

- **需求图片** 集中保存在 `data/attachments/`，不会把 Base64 图片写进配置或 Prompt。图片发送给模型是任务执行的一部分，并非只保留在本机。
- **验证截图**：执行器会要求 Codex 统一保存到 `task/<批次ID>/<任务ID>/screenshots/`，编码沙箱对这个目录额外开放写权限。工具若把截图另存到 worktree 等其他位置，这些文件不会自动纳入面板的统计与清理。
- **清理未引用图片**：保护已保存任务、所有保留历史批次和当前表单中的图片。取消上传表单或移除附件后，未被引用的图片可以在这里清理。
- **清理历史批次**：先选择已经结束的批次，再确认。移走其方案、日志、验证截图和 Review 报告，并移除运行记录。不会删除 worktree、Git 分支和开发代码；代码位置索引保存在 `data/worktree-records/`。
- **桌面应用** 会把文件移到系统废纸篓；清空系统废纸篓后才真正释放磁盘空间。恢复文件可以从废纸篓手动取回，但不会自动恢复面板运行记录。
- **浏览器调试模式** 使用 `data/recycle-bin/` 本地回收目录。文件仍占磁盘，需自行移出或删除才能释放空间。
- 有运行中任务时禁止清理，避免删除执行器正在读取的附件或报告。不会跟随符号链接删除外部文件。
- 存储统计不包含依赖、worktree、Codex 自身的聊天/会话缓存、登录凭据，以及其他应用的截图。不要通过删除整个 `~/.codex` 来清理图片，这可能同时影响登录和配置。

导出 JSON 只导出配置与图片引用，不打包图片文件；跨电脑迁移需同时保留 `data/attachments/` 和对应 `data/state.json`。

图片参数和临时会话参考：[官方 CLI 命令说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。

## 开发与验证

```bash
npm run dev        # 后端 3080 + Vite 5173；Ctrl+C 停止两个服务
npm run build      # 前后端 TypeScript 检查 + 生产构建
npm test           # 模拟 Codex 的真实 Git worktree / HTTP / 进程测试
```

桌面模式使用随机本机端口，避免固定端口冲突。API 变更需要本次服务会话 Token，拒绝外部 Origin 和非本地 Host；网页无 Node 权限，目录选择仅通过受限 Electron IPC 完成。

核心测试使用临时仓库和模拟 Codex，验证并发隔离、原暂存区保留、登录拦截、校验失败状态、取消、重启恢复、定时去重和端口释放，不消耗真实模型额度。

官方参考：[认证](https://learn.chatgpt.com/docs/auth)、[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。
