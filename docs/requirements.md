# 需求与功能设计

## 项目目标

CodexQueue 是本地 Codex CLI 开发任务调度工具，桌面窗口名称为 Auto Work。用户通过可视化表单配置多个独立开发任务，立即执行或每天定时执行，完成后统一查看实现、决策和遗留事项。

典型场景：晚上配置 2～3 个互相独立的页面或组件需求，让工具依次或并发运行，次日人工 Review 并合入代码。

## 需求边界

- 本地单人使用，服务只绑定 `127.0.0.1`，无需云端部署或面板账号系统。
- 复用本机 Codex CLI 登录；页面打开和每次执行批次前检查登录状态。
- 任务使用 Git worktree 隔离，基于批次开始时解析出的固定提交，保护原工作目录与暂存区。
- 普通技术选择不向用户中途提问，参考项目规范、官方推荐和成熟常见做法自行决定。
- 用户具体文案严格按原文使用，保留措辞、标点、数字和有语义的换行。缺失或冲突时不编造，记录待确认，继续可独立完成的部分。
- 不自动提交、推送或合并任务生成的业务代码。人工审核后自行处理任务分支。
- 关闭桌面窗口停止服务和任务，不在后台继续执行。

## 功能清单

| 模块 | 功能 |
| --- | --- |
| 任务管理 | 新增、编辑、删除任务；配置任务名称、Git 分支名、原始开发需求 Prompt；导出 JSON 配置 |
| 图片输入 | 文件选择、拖拽、截图粘贴、缩略图预览与移除；PNG/JPEG/WebP；每任务最多 8 张、每张 10 MB；内容哈希去重 |
| 项目检查 | 校验绝对路径和 Git 仓库根目录；解析基准提交；提示未提交修改；检测包管理器与校验脚本 |
| 执行配置 | 并发数量 1～5，默认 2；超时默认 60 分钟；可选模型、基准分支、依赖准备与校验命令 |
| 立即执行 | 创建批次，登录预检查，固定配置快照，并发运行独立任务 |
| 每日定时 | 使用本机时区；持久化设置；重启恢复未来调度；同一天最多自动触发一次；批次重叠时跳过并记录 |
| 状态与日志 | 等待、运行、完成、失败、阻塞、取消、中断；SSE 实时更新；按批次取消 |
| 交付产物 | plan.md、实施结果 JSON、真实校验退出码、todo-review.md、执行日志与错误原因 |
| 存储管理 | 分类占用统计、打开目录、清理未引用图片、清理选定历史批次；保护任务附件和开发代码 |
| 桌面生命周期 | Mac 双击入口、Windows 启动脚本；关闭窗口终止任务进程树并释放端口 |

## 单任务流水线

```mermaid
flowchart LR
  A[登录与项目检查] --> B[固定批次基准提交]
  B --> C[独立分支与 worktree]
  C --> D[只读规划]
  D --> E[依赖准备]
  E --> F[编码实现]
  F --> G[后端独立校验]
  G --> H[只读 Review]
  H --> I[保留代码、决策与遗留事项]
```

1. **准备**：校验 CLI、登录与项目；创建唯一分支，分支名附加批次和任务 ID。
2. **规划**：使用只读沙箱分析需求和代码，后端保存方案，不依赖模型自己遵守“禁止写代码”的提示。
3. **依赖**：可选安装依赖，按锁文件选择 npm/pnpm/Yarn，默认禁用安装生命周期脚本。
4. **实现**：原始需求、方案和参考图片一起传入；使用 workspace-write 沙箱；通过 JSON Schema 接收完成或阻塞状态、摘要、决策和待办。
5. **校验**：后端独立运行配置的命令，记录真实退出码。没有校验命令或校验失败时不标记完成。
6. **Review**：只读自查，区分已完成功能、已实现待复核决策、真正未完成事项和未验证内容。
7. **异常**：超时、失败、权限不足等保留错误和工作目录；不会取消其他任务。服务异常退出后，下次启动标记未完成任务为已中断。

## 自主决策优先级

1. 目标项目已有约定、依赖和实现模式。
2. 已安装依赖的官方推荐用法。
3. 成熟、常见的行业做法。
4. 满足需求的简单实现。

不做无关重构，不假装查证未实际查证的行业惯例。缺少必要凭据、权限或关键需求时保留阻塞说明；技术假设、决策理由和真实遗留问题分别记录。

## 存储规则

- 需求图片放在 `data/attachments/`，配置仅引用内容哈希。
- 约定的任务验证截图放在 `task/<批次ID>/<任务ID>/screenshots/`，另存其他位置的文件不自动纳入统计。
- 每次执行使用独立批次目录，避免覆盖历史产物。
- 运行期间不允许清理；保留已保存任务、剩余历史批次、当前任务表单引用的图片。
- 清理历史批次会移走相关报告和日志、移除运行记录，保留 worktree、Git 分支、代码及简要代码目录索引。
- 桌面版使用系统废纸篓；清空废纸篓后才释放磁盘空间。浏览器调试模式使用本地回收目录。
- 不清理 Codex 自身的聊天附件、登录凭据或其他应用文件。

## 不在首版范围内

- 云端托管、多人协作和面板账号权限。
- 自动推送、合并、发布或删除业务代码。
- 电脑关机、休眠或窗口关闭后继续定时运行。
- 自动恢复中断的模型会话、自动补跑错过的定时任务。
- 模型用量或网络可用性保证。
- 自动修复所有独立校验失败，或保证所有项目无需环境准备即可完成。
- 独立安装包和已签名的跨平台应用分发。

## 验收与验证范围

已实现 macOS 桌面启动与关闭，使用模拟 Codex、临时 Git 仓库和真实子进程运行集成测试，覆盖并发隔离、原暂存区保留、登录拦截、校验失败、取消、状态恢复、接口访问控制、定时去重、图片传递及清理保护。

真实模型开发任务未包含在自动化测试内；Windows 路径和进程启动逻辑已实现，尚未在 Windows 实机验收。
